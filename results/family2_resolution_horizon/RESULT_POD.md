## Split of work, and why it is split this way

**N=512 row → GPU pod.** Twenty fits plus sixty evaluations plus three cell
aggregations, all under the CUDA backend.

**N=128 and N=256, legs 2 and 3 → local Mac CPU.** These cells need no fitting:
their forty checkpoints already existed from the CPU run, and legs 2 and 3 only
change the rollout length of the handoff operator. They were kept on the Mac
because `run_family2.eval_one` requires the reloaded checkpoint to reproduce the
recorded `e_on` *exactly*, and that identity holds only on the backend that
produced the checkpoint. Evaluating CPU-fitted weights on the GPU would have
tripped `checkpoint reload did not reproduce e_on exactly` and stopped the run.
The eighty evaluations and four aggregations took seven minutes locally
(07:34 to 07:41:03Z).

**The four CPU-fitted N=512 narrow seeds were refitted on the pod, not reused.**
Mixing four CPU-fitted narrow seeds with six GPU-fitted narrow seeds against ten
GPU-fitted broad seeds would have put a backend difference inside the very
narrow-versus-broad contrast the cell measures. Refitting cost four extra GPU
fits, about six minutes. The originals are preserved unchanged under
`results/preserved_cpu_partial/` with checkpoints at
`pde_volume/family2/ckpt_preserved_cpu_partial/`, and a README there
giving the reason.

## Declared runtime departure

The N=512 row was computed under the CUDA runtime; the N=128 and N=256 rows are
entirely Apple-silicon CPU. This is noted in `RESULT.md` under `## Runtime`, is
machine-checkable in `results/RUNTIME.json`, and is derived from the
`platform.machine` field each training record already stored (`arm64` versus
`x86_64`), not asserted by hand.

Held fixed across the departure: jax/jaxlib 0.8.1, exponax 0.2.0, equinox 0.13.8,
numpy 2.5.3, scipy 1.17.1, Python 3.12; the model (16 modes, width 64, 4 layers),
optimiser, 8000-step schedule, batch 64, corpus generator, seeds, metric, and
every gate threshold. `STABILITY.json` and `GEOMETRY.json` were copied to the pod
rather than recomputed, so the support geometry and the stability screen are the
same float64 artifacts for all nine cells.

One pod-side environment shim was needed and is preserved at
`logs/pod_c1h12kov47rcm4/_runtime_path_POD_SHIM.py`. The Mac's
`pkg_scratch/scripts/band_check/_runtime_path.py` prepends that machine's uv
archive cache to `sys.path` and raises when the cache is absent, which it is on a
pod. The shim asserts the three pinned versions are the installed ones and
changes no path. The Mac file was not touched.

## The one code change

`render_markdown` in `run_family2.py` gained six lines that emit a `## Runtime`
section when `results/RUNTIME.json` exists. Display only: it reads no result,
touches no gate, and a run without that file renders exactly as before. It exists
so the runtime departure survives the next `aggregate-all` instead of being an
appended note that the aggregator would silently overwrite.
